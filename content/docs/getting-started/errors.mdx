The API uses standard HTTP status codes. `2xx` means success, `4xx` means something in the request needs to change, and `5xx` means something went wrong on Rehabify's side.

## The error object

Every error response has the same shape:

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "validation_error",
    "message": "patient.phone must be a valid phone number (E.164, e.g. +2348012345678).",
    "param": "patient.phone",
    "request_id": "req_5f2c9a1b7d3e4f60a1b2c3d4",
    "doc_url": "https://docs.physioaroundme.com/getting-started/errors#validation_error"
  }
}
```

| Field | Description |
| :--- | :--- |
| `type` | The broad category of error (see the table below). |
| `code` | A stable, machine-readable code. Branch on this value. |
| `message` | A human-readable explanation. It may change over time, so don't parse it. |
| `param` | The field or query parameter at fault, such as `patient.phone`. Present only when a specific field is at fault. |
| `request_id` | The request's ID. It matches the `X-Request-Id` header. Quote it to support. |
| `doc_url` | A link to this page, anchored at the error code. |
| `existing` | Only on `duplicate_partner_reference`: the `id` and `tracking_code` of the referral that already exists. |

### Error types

| `type` | Used for |
| :--- | :--- |
| `invalid_request_error` | Malformed requests, invalid fields, missing consent, inactive links and idempotency misuse |
| `authentication_error` | Missing or invalid API key |
| `permission_error` | Your organisation or key isn't allowed to do this |
| `not_found_error` | The resource or endpoint doesn't exist in this environment |
| `conflict_error` | The request conflicts with existing state |
| `rate_limit_error` | Too many requests |
| `api_error` | A problem on Rehabify's side, or a feature that isn't available yet |

| :--- | :--- | :--- | :--- |
| 400 | `invalid_request_error` | [`invalid_json`](#invalid_json) | Body is not valid JSON |
| 400 | `invalid_request_error` | [`invalid_parameter`](#invalid_parameter) | A query parameter is invalid (`param` set) |
| 401 | `authentication_error` | [`missing_api_key`](#missing_api_key) | No key supplied |
| 401 | `authentication_error` | [`invalid_api_key`](#invalid_api_key) | Key unknown or revoked |

| 404 | `not_found_error` | [`referral_not_found`](#referral_not_found) | No referral with that id / tracking code / partner_reference in this environment |

| 501 | `api_error` | [`feature_not_available`](#feature_not_available) | Endpoint not yet available in live (eligibility) |
| 503 | `api_error` | [`service_unavailable`](#service_unavailable) | Temporary outage — retry with backoff |

## Handling errors

| Situation | Retry? | How |
| :--- | :--- | :--- |
| `429 rate_limit_exceeded` | Yes | Wait for `Retry-After` seconds, then retry with backoff. |
| `500 internal_error`, `503 service_unavailable`, network timeouts | Yes | Exponential backoff with jitter, using the **same** `Idempotency-Key`. |
| `409 idempotency_request_in_progress` | Yes | Wait a moment, then retry with the same key and body. |
| `409 duplicate_partner_reference` | No | Use `error.existing` to fetch the referral that already exists. |
| Other `4xx` errors | No | Fix the request first. Retrying unchanged gives the same error. |

[Conventions](/docs/getting-started/conventions#rate-limits) includes a ready-made retry helper for Node.js and Python.

## 400 Bad Request

### `invalid_json` [#invalid_json]

The request body isn't valid JSON. Check for trailing commas, unescaped quotes or a truncated body, and send `Content-Type: application/json`.

### `invalid_parameter` [#invalid_parameter]

A query parameter is invalid, and `param` names it. Common causes: `limit` outside 1–100, a `status` value that isn't allowed for that endpoint, or a timestamp filter that isn't ISO-8601.

## 401 Unauthorized

### `missing_api_key` [#missing_api_key]

The request had no API key. Send `Authorization: Bearer <key>` or `X-API-Key: <key>`. See [Authentication](/docs/getting-started/authentication).

### `invalid_api_key` [#invalid_api_key]

The key isn't recognised or has been revoked. Check for copy errors and stray whitespace, and make sure your deployment loads the right secret. If the key was lost or revoked, create a new one in **Developers → API keys**.

## 403 Forbidden

### `partner_inactive` [#partner_inactive]

Your organisation hasn't been approved yet, or has been suspended. Contact [partners@physioaroundme.com](mailto:partners@physioaroundme.com).

### `production_access_required` [#production_access_required]

You used a live key, but your organisation doesn't have approved production access, either because it hasn't been granted yet or because it was suspended. Request production access in the Partner Portal, or use a sandbox key. See [Production access](/docs/getting-started/authentication#production-access-going-live).

### `sandbox_only` [#sandbox_only]

You called a sandbox-only endpoint (`/sandbox/*`) with a live key. Use a `sk_test_` key.

## 404 Not Found

### `referral_not_found` [#referral_not_found]

No referral with that `id`, `tracking_code` or `partner_reference` exists in this environment. You also get this error when the referral belongs to another partner, or to the other environment (for example, a sandbox referral fetched with a live key).

### `referral_link_not_found` [#referral_link_not_found]

No referral link matches the `id` (for `PATCH /partners/referral-links/{id}`) or the `public_code` (for the public lead endpoint).

### `resource_not_found` [#resource_not_found]

The endpoint doesn't exist. Check the path and make sure it includes `/v1`, for example `https://api.physioaroundme.com/v1/partners/referrals`.

## 409 Conflict

### `duplicate_partner_reference` [#duplicate_partner_reference]

A referral with this `partner_reference` already exists in this environment. The error tells you which one:

```json
{
  "error": {
    "type": "conflict_error",
    "code": "duplicate_partner_reference",
    "message": "A referral with partner_reference HMO-REF-2026-0091 already exists.",
    "request_id": "req_8a1d4c7e2b9f4a3c8d6e1f0a",
    "doc_url": "https://docs.physioaroundme.com/getting-started/errors#duplicate_partner_reference",
    "existing": { "id": "jd7f3k2m9x1q8w4e5r6t7y8u9i0o1p2a", "tracking_code": "RHB-4829173655" }
  }
}
```

If this is the same patient you referred before, use `existing.id` to fetch that referral instead of creating a new one. If it's a different referral, send a different `partner_reference`.

### `idempotency_request_in_progress` [#idempotency_request_in_progress]

Another request with the same `Idempotency-Key` is still being processed. Wait briefly, then retry with the same key and body. You'll get the original response.

### `webhook_endpoint_not_configured` [#webhook_endpoint_not_configured]

`POST /sandbox/trigger-webhook` was called, but no webhook endpoint is configured for this environment. Set one in **Developers → Webhooks** in the Partner Portal.

## 410 Gone

### `link_inactive` [#link_inactive]

Returned by the public lead endpoint when the referral link is inactive or past its `expires_at`. Reactivate the link (`PATCH /partners/referral-links/{id}` with `"status": "active"`) or create a new one. See [Referral links](/docs/api-reference/referral-links).

## 422 Unprocessable Entity

### `validation_error` [#validation_error]

A field failed validation. `param` names the field (for example `patient.phone`) and `message` explains the rule. Field rules are listed in [Create a referral](/docs/api-reference/referrals#create-a-referral).

### `consent_required` [#consent_required]

`consent.granted` is missing or isn't `true`. Rehabify only accepts referrals for patients who have agreed to be contacted. Capture consent first, then send `"consent": { "granted": true }`.

### `patient_ineligible` [#patient_ineligible]

Returned in sandbox when `patient.phone` is the magic number `+2348000000004`. No referral is created. Use it to test how your system handles a rejected referral.

### `idempotency_key_reused` [#idempotency_key_reused]

The `Idempotency-Key` was already used in the last 24 hours with a different request body. Use a new key whenever the body changes.

### `invalid_status_transition` [#invalid_status_transition]

`POST /sandbox/referrals/{id}/advance` asked for a status that can't follow the current one: either a move backwards, or a move out of a terminal status. See [Sandbox & testing](/docs/sandbox/testing#advance-a-referral).

## 429 Too Many Requests

### `rate_limit_exceeded` [#rate_limit_exceeded]

You've exceeded your rate limit: 10 requests per second in sandbox, or 20 per second in live (100 per second on enterprise contracts). The public lead endpoint allows 5 requests per 10 minutes per IP address. Wait for the number of seconds in the `Retry-After` header, then retry with backoff.

## 500 Internal Server Error

### `internal_error` [#internal_error]

Something unexpected went wrong on Rehabify's side. It's safe to retry with the same `Idempotency-Key`. If the error persists, contact support with the `request_id`.

## 501 Not Implemented

### `feature_not_available` [#feature_not_available]

The endpoint isn't available in live yet. Currently this applies to `POST /partners/eligibility`, which is [coming soon](/docs/api-reference/eligibility). Only a simulated preview is available, in sandbox.

## 503 Service Unavailable

### `service_unavailable` [#service_unavailable]

A temporary outage. Retry with exponential backoff, using the same `Idempotency-Key` for `POST` requests.
